## How this edition was made · 方法

The full list is machine-made and tracks 700+ repos. This edition is not. Every entry below was:

1. **Cloned and linted** with [`dsh-skill-lint`](../LINT.md) against [Spec 0.1](../SPEC.md) — the score shown is the linter's, unedited.
2. **Read in full** — `SKILL.md`, the directory layout, referenced scripts and references, README, tests.
3. **Judged on three questions**: Will an agent actually load and follow it? Is it honest about what it needs and what it can't do? Would I let it run on my machine?

What this edition is *not*: we did not execute every skill end-to-end inside a running dsh session. Where a verdict depends on that, it says so. Stars were a filter for candidates (verified + top of category), not a criterion for picking.

完整榜单由机器维护，本期不是。每一条都：① clone 后用 `dsh-skill-lint` 按规范 0.1 打分（分数原样呈现）；② 通读 SKILL.md、目录结构、引用的脚本与参考、README、测试；③ 用三个问题判断——agent 真的会加载并遵循它吗？它对自身需求与局限诚实吗？我愿意让它在我机器上跑吗？本期**没有**在运行中的 dsh 会话里端到端执行每个技能，凡依赖这一点的判断都有说明。Star 只用于筛候选，不是入选标准。

## ✦ Skill of the quarter · 本季之选

### [tt-a1i/archify](https://github.com/tt-a1i/archify) — `A 100`

The only skill in this review with zero findings, and it earns it. Archify turns a diagram request into a typed JSON spec, then makes the agent **validate before it can claim success** — `validate` and `deliver` return receipts, "a non-zero exit can never be described as success", and the instructions explicitly forbid the agent from reading renderer internals before writing a first candidate. That last rule is the tell: the author has watched agents wander and designed against it. Bounded reading, artifact-first, receipts as the definition of done. This is what a production skill looks like.

本次审读中唯一零发现的技能，而且实至名归。它把画图请求变成带类型的 JSON 规格，然后**强迫 agent 先校验再宣称完成**——`validate`/`deliver` 返回回执，"非零退出永远不能被描述为成功"，并明令 agent 在写出第一版之前不许去读渲染器源码。最后这条规则暴露了作者的经验：他见过 agent 乱逛，并针对性地设计了约束。有边界的阅读、先产物后细节、回执即完成——生产级技能就长这样。

## Patterns worth copying · 值得复制的模式

1. **Receipts, not claims.** archify, interactive-code-map and clawock all make a program, not the model, decide whether the work is done.
2. **Fit checks.** longgraph, modsearch and brooks-lint say when *not* to use them. Descriptions that only sell are the #1 warning in this review (DSK013).
3. **Progressive disclosure.** superdesign, ds-spec-loop and harmony-next route to one reference file per task. distilly and gongwen show the cost of not doing so.
4. **Permission before action.** find-plugins reports required permissions before install; atomgit stops after the PR. This is what "safe to run on my machine" looks like in text.
5. **Key hygiene as instructions.** dsh-media-skills writes the secret-handling rules into the skill itself, so the agent enforces them.

1. **回执而非宣称**——由程序而非模型判定完成。2. **适用性检查**——写明何时不该用；只会推销的 description 是本次最常见的警告。3. **渐进披露**——每个任务只路由到一份参考。4. **先授权后行动**——安装前汇报权限、PR 后停止。5. **密钥纪律写进技能**——让 agent 自己执行。

## Things we'd like to see fixed · 希望修复的问题

- Three picks ship **without a LICENSE file** (harmony-next, dsh-atomgit, agent-handoff). Add one; it's the difference between "can use" and "may use".
- Non-standard frontmatter keys (`whenToUse`, `trigger`, `do-not-trigger`, `official`) appear across several repos. They're a good idea — which is why the spec should absorb them. Proposal open in [SPEC.md](../SPEC.md).
- One popular workspace app instructs the agent to `curl … | bash` an installer and to "execute immediately, do not just show the steps". That is exactly the pattern DSK031 exists for. Not picked.

- 三个入选项**没有 LICENSE 文件**。加上它，这是"能用"与"可以用"的区别。
- 多个仓库使用非标准键（`whenToUse`、`trigger`、`do-not-trigger`、`official`）。这是好主意——所以规范应该吸收它们，提案见 SPEC.md。
- 一个热门工作台应用要求 agent `curl … | bash` 安装器并"立即执行、不要只展示步骤"。这正是 DSK031 存在的原因。未入选。
